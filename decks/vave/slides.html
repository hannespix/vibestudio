05 / git in zwei minuten

Ein Ordner mit Gedächtnis.

commit

Ein Schnappschuss

mit Nachricht: wer, was, warum.

branch

Ein Abzweig

zum Ausprobieren, ohne zu stören.

diff

Der Unterschied

Zeile für Zeile: neu, weg, anders.

pull request

Der Vorschlag

prüfen, besprechen, zusammenführen.

remote

Gemeinsame Kopie

auf GitHub, GitLab oder eigenem Server.

Das Repo gehört euch. Egal, welcher Agent als Nächstes kommt.

2 Minuten. Git ist ein Ordner, der sich an jeden gespeicherten Stand erinnert. Ein Commit ist ein Schnappschuss mit Nachricht. Ein Branch ist ein Abzweig zum Ausprobieren, während der Hauptstand stabil bleibt. Der Diff zeigt Zeile für Zeile, was sich geändert hat; deshalb kann man die Arbeit eines Agenten überhaupt prüfen. Ein Pull Request (bei GitLab Merge Request) ist der Vorschlag, einen Branch zusammenzuführen: Diff, Gespräch und automatische Prüfungen an einem Ort. Der Remote ist die gemeinsame Kopie auf GitHub, GitLab oder dem eigenen Server. Für alle, die Pläne kennen: Commit ist der Planstand mit Index, Branch die Variante, Diff die Änderungswolke, Pull Request die Freigabe. Und das Wichtigste: Das Repo gehört euch. Claude Code, Codex, OpenCode – der nächste Agent liest denselben Stand und arbeitet weiter. Quellen: https://git-scm.com/book/de/v2 ; https://docs.github.com/en/pull-requests . Stand: 27.09.2026. Kapitel 8. Drei Regeln und ein Satz zum Merken. Das Motiv ist ein Kanaldeckel über einem Revisionsschacht: Prüfen heißt, den Deckel zu öffnen und hineinzuschauen.
08 / was gut funktioniert

Drei Regeln.

Klein beauftragen.

Eine Sache pro Runde.

Alles ins Repo.

Notizen, Regeln, Code. Dann darf der Chat vergessen.

Nichts ungeprüft.

Ausprobieren, Diff lesen, dann freigeben.

Und immer: Zugangsdaten nie ins Repo, Kundendaten nur mit Freigabe.

1,5 Minuten. Drei Regeln, die fast alle Probleme verhindern. Klein beauftragen: eine Sache pro Runde, lieber fünf kleine Pull Requests als ein großer. Alles ins Repo: Ziel und Einstieg in die README, Entscheidungen in kurze Notizen, dauerhafte Regeln in die Anweisungsdatei des Agenten, also CLAUDE.md oder AGENTS.md; dann darf der Chat vergessen. Nichts ungeprüft: ausprobieren, Diff lesen, erst dann freigeben, wie eine Planfreigabe. Und immer: Passwörter und Schlüssel gehören nie in versionierte Dateien, Kundendaten nur mit Freigabe und einem Modellzugang, dessen Datenschutzbedingungen passen. Quellen: https://code.claude.com/docs/en/best-practices ; https://agents.md . Stand: 27.09.2026.
