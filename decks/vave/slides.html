Kapitel 6. Git in drei Minuten und eine Brücke zu dem, was jede Planung ohnehin tut. Das Motiv, der obere Bogen einer Schallplatte, ist eine erzeugte Grafik: jede Rille eine Aufzeichnung.
06 / git in drei minuten

Ein Ordner mit Gedächtnis.

commit

Ein Schnappschuss

mit Nachricht, wer was warum geändert hat.

branch

Ein Abzweig

zum Ausprobieren, ohne den Stand zu stören.

diff

Der Unterschied

Zeile für Zeile: was neu ist, was weg ist.

pull request

Der Vorschlag

prüfen, besprechen, zusammenführen.

remote

Gemeinsame Kopie

auf GitHub, GitLab oder dem eigenen Server.

Jeder Stand bleibt erreichbar. Geprüft wird, bevor etwas zählt.

2 Minuten. Git ist ein Ordner, der sich an jeden gespeicherten Stand erinnert. Ein Commit ist ein Schnappschuss aller Dateien mit einer kurzen Nachricht; Commits sind billig, man macht viele. Ein Branch ist ein Abzweig: Dort probiert man etwas aus, während main stabil bleibt. Der Diff zeigt exakt, was sich geändert hat, deshalb kann man die Arbeit eines Agenten überhaupt prüfen. Ein Pull Request (bei GitLab Merge Request) ist der Vorschlag, einen Branch zusammenzuführen: Diff, Gespräch und automatische Prüfungen an einem Ort; wer freigibt, entscheidet. Der Remote ist die gemeinsame Kopie auf einer Plattform. Der Graph unten erzählt genau das. Quellen: https://git-scm.com/book/de/v2 ; https://docs.github.com/en/pull-requests . Stand: 27.09.2026.

Kapitel 9: Wie klingt ein Auftrag, der funktioniert? Das Motiv, eine gebogene Lichtwand, ist eine erzeugte Grafik.
09 / ein guter auftrag

So klingt ein Auftrag, der funktioniert.

Baue einen Flächen- und Materialkalkulator für Messestände: Eingabe sind Standmaße und Modultypen, Ausgabe sind Flächen, Materialliste und Richtpreis. Nutze die Preise aus preise.csv und die Modulmaße aus der README. Kleine Web-App ohne Server, mit Tests für die Rechenlogik: ein Stand 6 × 4 m mit zwei Ecken muss 24 m² und 14 Wandmodule ergeben. Keine Kundendaten. Ergebnis als Pull Request mit kurzer README.

Ziel

Was entstehen soll, in einem Satz.

Kontext

Welche Dateien und Regeln gelten.

Abnahme

Woran man erkennt, dass es stimmt.

Grenzen

Was nicht passieren darf, wie geliefert wird.

Ein Auftrag, vier Sätze. Der Rest ist Ausprobieren und Zurückmelden.

2 Minuten. Den Auftrag einmal vorlesen. Vier Bausteine: Ziel in einem Satz; Kontext, welche Dateien und Regeln gelten; Abnahme, ein konkretes Beispiel mit erwartetem Ergebnis, das der Agent als Test einbauen kann; Grenzen, was nicht passieren darf und wie geliefert wird. Der Trick mit der Abnahme: Ein einziges konkretes Beispiel ist mehr wert als drei Absätze Erklärung. Preise und Module sind erfunden, das Beispiel dient der Form.
09 / runde für runde

Klein anfangen.
Jede Woche eine Runde.

Der Kalkulator in fünf Runden. Jede Runde ein Pull Request, jeder Merge ein Rückweg.

1 Minute. So wächst ein Werkzeug: Runde eins nur die Rechenlogik mit Tests, noch ohne Oberfläche. Runde zwei die Eingabemaske. Runde drei die Materialliste als PDF. Runde vier die Preise aus der Materialkartei. Runde fünf ein Link, den der Kunde öffnen kann. Fünf Wochen, fünf Nachmittage, und jeder Stand war für sich brauchbar. Wenn Runde vier schiefgeht, steht Runde drei noch.
